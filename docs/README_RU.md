# ChunkDoctor — документация на русском

[← Back to the main README](../README.md)

ChunkDoctor — плагин для Paper 1.21.8, который постепенно анализирует уже
загруженные чанки и оценивает **потенциальный риск нагрузки** по шкале 0–100.
Он объясняет оценку, показывает наблюдаемые факторы и предлагает только
релевантные рекомендации.

> ChunkDoctor не измеряет «TPS конкретного чанка» и не заменяет профилировщик.
> Высокий risk score означает концентрацию потенциально дорогих объектов, но не
> доказывает, что этот чанк — единственная причина лагов. Для времени выполнения
> задач и плагинов дополнительно используйте встроенный в Paper spark.

## Требования

- Paper 1.21.8;
- Java 21;
- для сборки достаточно Gradle Wrapper из репозитория.

Плагин не использует NMS, CraftBukkit, reflection, SQLite или обязательные
сторонние плагины. В JAR затеняется только Gson.

## Архитектура и потоки

Работа разделена на два строгих этапа:

1. `ChunkSnapshotCollector` на серверном потоке читает только загруженный чанк и
   создаёт immutable `ChunkSnapshot` без ссылок на Bukkit-объекты.
2. Ограниченный `AnalysisPipeline` рассчитывает score, сортирует причины и
   строит рекомендации на worker-потоках. Результат возвращается на серверный
   поток перед обновлением кэша и уведомлением игроков.

`MonitoringService` обходит разрешённые миры по кругу, соблюдает лимит чанков,
наносекундный deadline, cooldown повторного анализа и TPS-гистерезис.
Очередь анализа ограничена; при заполнении новые задачи не накапливаются.

Фоновый мониторинг не перебирает блоки. `/cd deep` — единственный полный
блочный анализ: он работает только с текущим загруженным чанком, делится на
тик-срезы, ограничен числом блоков, временем тика, общей длительностью и числом
одновременных запусков.

Основные пакеты:

| Пакет | Назначение |
|---|---|
| `analysis` | синхронные снимки, анализ, bounded pipeline и deep scan |
| `monitoring` | пассивный обход и потокобезопасный кэш |
| `scoring` | независимый от Bukkit нелинейный risk score |
| `recommendation` | советы на основе фактических метрик |
| `report` | модель и атомарный асинхронный JSON-экспорт |
| `notification` | cooldown и PDC-настройка игрока |
| `message` | Adventure и MiniMessage |
| `command` | permissions, validation, UI и tab completion |
| `config` | immutable-конфигурация и fail-safe валидация |

## Сборка

Windows:

```powershell
.\gradlew.bat build
```

Linux/macOS:

```bash
./gradlew build
```

Production JAR:

```text
build/libs/ChunkDoctor-1.0.0.jar
```

`ChunkDoctor-1.0.0-plain.jar` не содержит Gson и не предназначен для установки.
Wrapper закреплён на Gradle 9.4.1 и проверяет официальный SHA-256 дистрибутива.

## Установка

1. Остановите сервер.
2. Скопируйте `build/libs/ChunkDoctor-1.0.0.jar` в `plugins/`.
3. Запустите Paper 1.21.8 на Java 21.
4. Проверьте `plugins/ChunkDoctor/config.yml`.
5. Выполните `/cd status`.

Не используйте `/reload` сервера. Для конфигурации ChunkDoctor существует
безопасная команда `/cd reload`.

## Команды

| Команда | Назначение | Консоль |
|---|---|---|
| `/cd help` | справка | да |
| `/cd status` | состояние, очередь и бюджет | да |
| `/cd scan [radius]` | быстрый скан загруженных чанков | нет |
| `/cd deep` | глубокий скан текущего чанка | нет |
| `/cd top [page]` | рейтинг результатов | да |
| `/cd info <world> <x> <z>` | подробный результат | да |
| `/cd teleport <world> <x> <z>` | безопасная телепортация | нет |
| `/cd export` | JSON всех результатов | да |
| `/cd export <world> <x> <z>` | JSON одного результата | да |
| `/cd reload` | перечитать и проверить config.yml | да |
| `/cd start` / `/cd stop` | управление мониторингом | да |
| `/cd clear [confirm]` | двухшаговая очистка кэша | да |
| `/cd notify` | переключить личные уведомления | нет |

Радиус ручного скана — квадрат по Chebyshev distance. Незагруженные чанки
пропускаются и никогда не загружаются ради анализа.

## Конфигурация

Полный файл с комментариями создаётся как `plugins/ChunkDoctor/config.yml`.

- `monitoring.interval-ticks` — период одного небольшого цикла.
- `monitoring.chunks-per-cycle` — верхний предел снимков за цикл.
- `monitoring.max-milliseconds-per-tick` — deadline сбора снимков.
- `monitoring.rescan-cooldown-seconds` — защита от частого повторного анализа.
- `monitoring.result-expiration-minutes` — срок жизни результата в памяти.
- `monitoring.pause-below-tps` / `resume-above-tps` — гистерезис паузы.
- `monitoring.maximum-pending-analyses` — жёсткая граница очереди.
- `worlds.mode` — `blacklist` или `whitelist`; имена сравниваются без регистра.
- `manual-scan.maximum-radius` / `maximum-chunks` — два независимых лимита.
- `deep-scan.*` — block budget, time budget, timeout и concurrency.
- `risk.weights.*` — базовые веса наблюдаемых объектов.
- `risk.excess-thresholds.*` — пороги нелинейного штрафа.
- `notifications.*` — уровень, прирост score и cooldown.
- `export.directory` — только одно безопасное относительное имя каталога.
- `messages.*` — MiniMessage-шаблоны.

Числа автоматически ограничиваются безопасными диапазонами. Некорректный
`worlds.mode`, небезопасный путь экспорта или пересекающиеся TPS-пороги не
роняют плагин: используется безопасное значение и пишется предупреждение.
Изменение размера worker pool требует перезапуска; остальные runtime-бюджеты
применяются после `/cd reload`.

## Как рассчитывается risk score

Score состоит не только из суммы:

1. базовые вклады `count × weight`;
2. квадратичные штрафы после настраиваемых excess-порогов;
3. дополнительный штраф за максимальную плотность сущностей, block entities или
   редстоун-компонентов;
4. ограничение результата диапазоном 0–100.

Уровни по умолчанию:

| Score | Уровень |
|---:|---|
| 0–29 | LOW |
| 30–59 | MEDIUM |
| 60–79 | HIGH |
| 80–100 | CRITICAL |

`HIGH` confidence выдаётся полному завершённому deep scan. Быстрый результат
имеет `MEDIUM`, когда entity data загружены и рядом есть игрок, иначе `LOW`.
Это честно отражает ограниченность наблюдения, а не качество сервера.

## Уведомления

Игрок с `chunkdoctor.notify` получает уведомление при новом CRITICAL-чанке,
значительном росте score или завершении deep scan. Для обычных предупреждений
действует cooldown по чанку. `/cd notify` сохраняет отключение в PDC игрока.

## JSON-отчёт

Запись выполняется на выделенном I/O-потоке во временный файл с последующим
атомарным перемещением. Путь нормализуется и обязан оставаться внутри каталога
данных плагина.

Сокращённый пример:

```json

  "generatedAt": "2026-07-28T12:00:00Z",
  "pluginVersion": "1.0.0",
  "serverVersion": "Paper 1.21.8",
  "summary": {
    "analyzedChunks": 1,
    "lowRiskChunks": 0,
    "mediumRiskChunks": 0,
    "highRiskChunks": 0,
    "criticalChunks": 1
  },
  "chunks": [{
    "key": {
      "worldId": "00000000-0000-0000-0000-000000000001",
      "worldName": "world",

      "chunkZ": -18
```

## Production-рекомендации

- Начните с `chunks-per-cycle: 2` и `max-milliseconds-per-tick: 2.0`.
- Не повышайте deep block budget без проверки MSPT в spark.
- Используйте whitelist на сетях с большим числом служебных миров.
- Экспортируйте данные перед очисткой кэша.
- Сравнивайте score с профилем spark и реальным MSPT, а не изолированно.
- Не выдавайте export/teleport/clear обычным игрокам.

## Ограничения

- Quick scan не перебирает блоки, поэтому поршни и обычный редстоун появляются
  только после deep scan.
- Entity data не форсируются, если Paper сообщает, что они не загружены.
- Активность оценивается только через публичные свойства блока (lit/enabled).
- Deep scan отдельно считает запитанные публично определяемые редстоун-компоненты.
- Кэш хранится в памяти и очищается при рестарте.
- Чанк может измениться сразу после снимка; timestamp показывает момент наблюдения.

## Troubleshooting

**Нет результатов:** проверьте `/cd status`, whitelist/blacklist, TPS-порог и
наличие загруженных чанков.

**Мониторинг постоянно на паузе:** сравните `/tps` и пороги
`pause-below-tps`/`resume-above-tps`. Между ними должна быть разница.

**Deep scan остановлен по timeout:** уменьшите активную высоту мира/нагрузку либо
аккуратно увеличьте `maximum-duration-seconds`; не увеличивайте сразу time budget.

**Экспорт не создаётся:** проверьте права записи в `plugins/ChunkDoctor/` и лог.
Пути с `/`, `\`, `:`, `..` намеренно отклоняются.

**Score высокий, но TPS нормальный:** это допустимо. Score — индикатор риска и
приоритет ручной проверки, а не измерение времени тика.

## Тесты

```bash
./gradlew test
```

Unit-тесты не поднимают Minecraft и проверяют чистую логику score, уровни,
штрафы, рекомендации, сортировку, пагинацию, config validation, JSON и ChunkKey.

## Чек-лист ручного тестирования

- [ ] Сервер Paper 1.21.8 запускается на Java 21 без warning/error ChunkDoctor.
- [ ] `/cd status` показывает bounded queue и runtime budget.
- [ ] `/cd scan` не загружает соседние выгруженные чанки.
- [ ] `/cd scan 2` сообщает число принятых только загруженных чанков.
- [ ] При TPS ниже порога статус показывает TPS-паузу; после восстановления — нет.
- [ ] `/cd deep` показывает progress и не создаёт заметного длинного тика.
- [ ] Выгрузка мира отменяет его deep scan.
- [ ] Второй deep scan блокируется при `maximum-concurrent-scans: 1`.
- [ ] `/cd top`, пагинация, info-кнопка и TP-кнопка работают.
- [ ] TP отклоняет выгруженный чанк и небезопасную поверхность.
- [ ] `/cd export` создаёт валидный UTF-8 JSON внутри data folder.
- [ ] `export.directory: ../escape` отклоняется и не пишет за пределы плагина.
- [ ] `/cd clear` без второго `confirm` ничего не удаляет.
- [ ] Игрок без каждого отдельного permission получает отказ.
- [ ] `/cd notify` сохраняется после перезахода игрока.
- [ ] `/cd reload` переживает отрицательные/слишком большие значения.
- [ ] Остановка сервера отменяет задачи и worker threads без stack trace.
